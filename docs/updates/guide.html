GitHub에 올린 사이트 코드를 본인 관리자 계정으로 Mac에 반영합니다. Mac에서 한 번 설정한 다음, 홈 → 사이트 업데이트를 사용하세요. 소개·이력서 편집은 기존 저장 버튼을 씁니다.

진행 · 확인한 정확한 버전만 반영합니다. 검증 중에는 기존 사이트를 유지하고, 재시작 중 끊겨도 화면이 다시 연결합니다.

Mac에서 처음 한 번

먼저 기존 수동 업데이트 절차로 이 기능을 받아 세 서버를 재시작하세요. 기본 data/와 기본 이름의 사용자 LaunchAgent 3개가 필요합니다.

npm run setup-updater -- --origin https://starlightforge.duckdns.org
launchctl kickstart -k "gui/$(id -u)/org.starlightforge.portfolio"
launchctl kickstart -k "gui/$(id -u)/org.starlightforge.chat"
launchctl kickstart -k "gui/$(id -u)/kr.haru.jlpt"
npm run update-status

Mac의 앱 저장소 폴더에서 실행하세요. 관리자 비밀번호를 다시 만들 필요는 없습니다. Mac 사용자 로그인 후 작업자가 실행됩니다.

오류가 나면

npm run update-status와 .site-updater/worker-errors.log를 확인하세요. 백업 번호의 backups/JOB/manifest.json이 있어야 전체 백업이 검증된 것입니다. 백업·이전 의존성은 자동으로 지우지 않습니다.

중단 · 정지 뒤 실패하면 Mac에서 복구가 필요합니다. 자동 롤백은 하지 않습니다. 이전 코드만 실행하면 새 DB와 맞지 않을 수 있으므로 코드·전체 데이터·의존성을 함께 확인합니다. 종료를 확인하지 않고 DB를 덮어쓰지 마세요.

수동 복구의 순서

작업자와 세 앱을 정지하고 실제 종료를 확인 → 현재 상태를 추가 보존 → manifest의 원래 SHA로 복구 브랜치 생성 → 검증된 전체 data와 이전 의존성 사본 준비 → 현재 자료를 보존한 채 교체 → 세 앱을 시작해 로그인과 기능 확인. 복구 브랜치에서는 버튼 업데이트가 차단됩니다.

설정이 중간에 실패했다면

기존 작업자를 내리고 실제 종료를 확인하세요. .site-updater/와 사용자 LaunchAgents의 org.starlightforge.updater.plist를 저장소 밖의 새 비공개 폴더로 옮겨 보존한 뒤, 정상 starlightForge 설치에서 다시 설정합니다. 진행 중인 적용이 있었다면 먼저 수동 복구를 마쳐야 합니다. 같은 절차로 작업자 자체를 갱신할 수 있습니다.

이 문서는 외부 자산 없이 오프라인에서도 열립니다. 구체적인 경로·복구 명령과 설치 조건은 저장소의 deploy/MAC-UPDATES.md에 함께 보관합니다. 실제 Mac의 launchctl·인증서 읽기 권한·절전·운영 도메인 재연결은 Mac에서 최종 확인해야 합니다.
