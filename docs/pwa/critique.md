## 구현 후 독립 코드 검토와 실행 증거

pragmatist-codex가 서버 통합·푸시 저장소/전송·CLI·서비스 워커를 읽기 전용으로 검토했다. P2 1건: `PORTFOLIO_DATA_DIR`만 설정했을 때 서버와 CLI가 다른 푸시 경로를 사용하는 결함. `lib/push-paths.mjs`를 세 진입점에서 공통 사용하도록 채택·수정했다. 실제 CLI 생성→서비스 읽기→빈 기기 발송 명령(외부 전송 없음)→기존 키 보존의 회귀 테스트를 추가했다. 재검토에서 해결을 확인했으며 변경분의 새 결함은 없었다. 구현 결함 채택1/1, 미해결 ★0.

- Windows Node24.15.0 전체 테스트 **82/82 통과**. 기존 학습·채팅·포트폴리오 회귀 포함.
- 새 검증26개: 푸시 서비스/전송12, 클라이언트6, 서비스 워커3, HTTP 인증/구독/재시작4, 경로 CLI1 = **26개**. 기존56개와 합쳐82개다.
- HTTP 프록시 시험은 native HTTP Host/Origin 헤더로 실제 역방향 프록시 조건을 재현했다. Node fetch가 Host 재정의를 적용하지 않는 시험 도구 문제를 수정했다.
- 브라우저 임시 계정/DB에서 설치 안내·미설정 상태·비활성 버튼과 기존 상단탭/하위메뉴를 확인했다. 390px 화면의 가로 넘침 없음.
- 실제 푸시 제공자로 알림을 보내지 않았다. 암호화·DNS 고정·HTTP 응답은 모의 transport, OS push/click은 VM으로 검증했다. Mac·Nginx·폰 배경 수신·재로그인은 배포 후 사용자 기기 확인 항목이다.
