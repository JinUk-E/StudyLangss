# 별빛공방 PWA·Web Push 구현 범위

2026-10-20 · main-codex · L 등급: 외부 푸시 계약, 기기 구독 저장, 설치·배포 변경.

사용자 승인 근거: “진행해줘 / 푸시기능도 추가해서”. 기존 웹을 홈 화면에 설치하고 푸시를 켜는 범위의 구현 지시다. 주간 검색·리포트 자동화 자체는 기존 별도 기획으로 남는다. 이번에는 설치, 기기별 구독/해제, 테스트 수신, 서버에서 쓸 전달 모듈과 수동 발송 명령을 완성한다. 실제 휴대폰 알림 권한은 사용자가 직접 허용한다.

## 동작과 소유권

- 앱 이름 별빛공방, 식별자 `/`, 시작 `/app/`, 범위 `/`, standalone. 기존 홈/AI 대화/학습 이동 유지.
- 홈 하위 메뉴에 앱 설치·알림. `/app/`는 기존 Basic 인증으로 보호. 설치 안내와 이 기기의 상태·구독·해제·테스트, 등록 기기 목록/삭제를 제공.
- 루트 manifest·아이콘·`/sw.js`는 비밀 없는 공개 자원. 서비스 워커는 push/click만 처리하며 fetch 캐시를 추가하지 않는다. 개인 대화·학습·리포트의 오프라인 저장은 이번 범위 아님.
- 기존 portfolio 서버가 자원·인증된 `/api/portfolio/push/` API와 SQLite 기기 저장소를 소유. 새 포트 없음. 기존 Nginx `/`·`/api/portfolio/` 전달 사용.
- 권한 요청은 `이 기기에서 알림 켜기` 클릭에서만 한다. 아이폰은 홈 화면 설치 후 실행하도록 안내. 설치와 알림 권한·서버 등록을 각각 구분한다. 브라우저의 알림 거절·지원 없음·HTTPS 필요 상태를 표시한다.
- `beforeinstallprompt`가 있으면 설치 버튼, 없으면 Safari/Chrome 메뉴 안내. 설치됨을 모든 브라우저에서 확정할 수 있다고 주장하지 않는다.

## 푸시 계약

- 표준 `web-push` 패키지의 VAPID/aes128gcm 사용. 설정 명령이 origin·연락처·키를 Git 제외 파일에 0600으로 저장. 기존 키는 덮어쓰지 않는다. 미설정/설정 손상 시 푸시만 비활성화하고 웹은 유지한다. **VAPID 공개키만** 인증된 설정 API에서 브라우저에 전달하며 개인키·구독 endpoint/암호화 키는 API 응답·로그에 노출하지 않는다.
- 구독은 인증·동일 출처 쓰기 API로만 등록. 최대10기기, endpoint 고유, 재등록 갱신. 표시 이름·타임스탬프·불투명 ID·마지막 전달 상태만 기기 목록에 반환.
- 구독 endpoint는 HTTPS·기본443·userinfo/fragment 없음. 알려진 Apple/Google/Mozilla 푸시 서비스만 허용하고 DNS가 공인 주소인지 검증해 실제 연결에 고정한다. IP·사설 주소·리다이렉트는 불허. 신뢰 호스트 확장은 코드 검토로만 한다.
- p256dh EC 공개키·auth 길이와 형식을 검증. 요청·응답 크기 제한, 발송 제한시간, 동시 발송 제한과 기기별 테스트 쿨다운. 임의 공개 발송 API 없음.
- 테스트는 선택한 기기 1개에 고정 문구만 전송한다. CLI는 Mac 사용자만 실행하며 대상 ID 또는 명시적 전체 대상으로 일반 상태 알림을 보낼 수 있다. 미래 리포트는 이 모듈로 연동 가능하나 지금은 예약이 없다.
- 기본 알림은 잠금 화면에 민감한 본문 없이 “별빛공방에 새 알림이 있어요”와 앱 링크. payload와 클릭 URL은 고정된 같은 출처 경로만 허용, 외부 이동 금지. push마다 알림을 표시하며 data-only push는 안 함.
- 404/410 구독은 정리. 429·5xx·네트워크 오류·timeout은 결과 구분 후 자동 재전송 없음. 수신이 아닌 푸시 서비스의 접수 상태만 성공으로 표시한다. 앱 삭제/브라우저 차단으로 무효 구독이 남을 수 있어 기기 관리에서 삭제 가능.
- 기기 삭제 뒤 이미 푸시 서비스가 접수한 메시지의 회수는 보장하지 않는다. 현재 기기를 삭제하면 서버 수신 등록과 브라우저 구독을 해제하며 OS 알림 허용은 별개로 남을 수 있음을 표시한다. 다른 기기는 서버에서만 삭제하므로 해당 브라우저 구독은 남을 수 있다. 브라우저 구독 갱신/키 변경은 설정 페이지를 다시 열어 재연결 안내한다. VAPID 파일/DB는 개인 백업 대상이나 공개 JSON 백업에 섞지 않는다. 이번 백업 산출물은 서버를 멈춘 뒤 두 파일을 안전한 개인 위치에 복사·복원하는 안내까지이며 새 백업 명령은 추가하지 않는다.

## 검증·배포

- manifest·아이콘·SW 공개 접근/MIME/scope, 개인정보 API·설정 인증, CSRF, SSRF endpoint·DNS 고정·리다이렉트 차단, 크기/기기수 한도, 키 보존, 구독 재시작 보존, 404/410 정리, 429/timeout·중복 테스트 쿨다운, 비밀값 미반환 검증.
- 서비스 워커 push→알림과 click→동일 출처 이동을 모의 환경 검증. 브라우저에서 설치 안내·미설정/지원상태·390px 배치 확인. 실제 폰의 OS 권한·백그라운드 수신, 설치 앱 최초 실행·알림 클릭의 Basic 재로그인은 사용자 기기에서 설치 후 확인해야 한다.
- Mac: git pull → npm ci → setup-push(최초1회) → portfolio/chat/study 재시작. Nginx에 별도 신규 경로가 필요한지 예제와 대조하고 모든 서비스가 같은 HTTPS origin인지 확인한다.
- 정상 HTTPS PWA 설치는 APK 설치나 iOS 미서명 앱 실행과 다르며 앱스토어 심사를 요구하지 않는다. 다만 인증서 문제·악성 사이트 판정·회사 관리 정책·브라우저 지원/알림 차단으로 제한될 수 있다. 절대 차단되지 않는다고 보장하지 않는다.

기획 비판 기록과 동결 기록은 같은 디렉터리에 남긴다. 사용자가 이미 승인한 PWA·푸시 범위에서 기술 세부를 확정하며 추가 외부 CLI로 사설 문서를 전송하지 않는다.
