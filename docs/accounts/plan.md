# 계정별 권한과 개인 자료 분리

2026-10-20 · main-codex · L — 인증·개인 자료·기존 DB/구독 이전 변경.

사용자가 승인한 “응 그렇게 추가할 수있게 해줘”에 따라 관리자가 아이디·비밀번호·학습/AI 권한을 설정하고 활성화·중지하는 기능을 구현한다. 기존 단일 계정은 고정 관리자(owner)로 유지한다. 공개 홈·게시한 포트폴리오는 계속 공개다.

## 계정과 인증

- 기존 Basic 인증을 유지한다. 비밀번호는 12~256자 scrypt 해시, 평문 조회/응답/로그 없음. 계정 생성·권한 변경·중지·비밀번호 재설정은 관리자만 가능하다.
- setup-auth는 공통 DB 쓰기 잠금 안에서 이름 충돌을 확인하고 bootstrap 파일을 교체해 owner 검증값을 동기화한다. 세 서버 재시작 때도 bootstrap 변경분을 확인한다. 변경이 없으면 DB의 사용자 구성을 덮어쓰지 않는다. 관리자 새 이름이 다른 계정의 현재/과거 이름과 충돌하면 설정 명령은 기존 인증 파일을 보존하고 거부한다. 파일을 수동 변조해 충돌한 경우 서버는 fail closed한다.
- 공통 accounts.sqlite를 AUTH_FILE 옆에 두며 AUTH_USERS_FILE로 변경 가능. 세 서버가 같은 DB를 읽는다. 기존 auth.json의 관리자 검증값을 보존하여 최초 생성 시 owner로 등록한다. setup-auth는 관리자 복구 수단이며 관리자 아이디/비밀번호를 바꿔도 owner의 개인 자료 소유권은 유지된다.
- 최대30개 계정. 신규 계정은 study/chat 중 최소 하나를 명시 선택. 관리자 승격·관리자 중지·삭제는 UI에서 허용하지 않는다. 사용자 이름은 생성 후 고정하며 다른 사람에게 재사용하지 않는다. 삭제 대신 중지를 사용한다.
- 매 요청마다 DB의 활성화·권한·버전을 확인한다. 비밀번호 해시 캐시는 계정 버전과 함께 확인하며, 변경 뒤 기존 캐시로 통과시키지 않는다. 해시 계산 중 변경된 경우에도 재확인한다. 변경은 새 요청부터 모든 서버에 반영된다. 이미 처리 중인 학습 요청은 끝날 수 있고 채팅 스트림은 주기적 확인으로 중지한다.
- 브라우저 Basic 방식의 로그아웃/계정 전환 제약은 안내한다. 현재 관리자 인증 파일과 계정 DB는 Git/학습 백업에 포함하지 않는다.

## 권한 경계

| 권한 | 접근 |
|---|---|
| owner 관리자 | 모든 기능, 공개 콘텐츠 편집, 계정 관리 |
| study | 학습 화면과 해당 API, 학습용 설명/음성, 본인 학습 백업/복원 |
| chat | AI 대화 화면과 검색·생성 API, 본인 대화 기록 |
| 인증된 계정 공통 | 본인 PWA 설치·알림 설정과 기기 목록/테스트·해제 |

- 화면과 API를 함께 검사한다. 다른 사용자 ID를 URL/body로 보내도 자기 계정 범위를 바꿀 수 없다. 비공개 이력서·관리·업로드·계정 API는 관리자 전용이다.
- 공통 세션 조회는 개인 데이터 없이 아이디·권한만 반환한다. 공개 홈의 선택적 조회는 인증 누락 시 로그인 창을 강제로 띄우지 않는다. 비공개 페이지는 인증된 me 조회로 확정한다. 메뉴 표시는 보조이며 API 검사가 최종 권한이다.
- 일반 사용자는 서버의 Ollama 주소를 바꿀 수 없다. 학습 모델/개인 목표 급수는 선택하되 실제 학습 AI 연결 주소는 관리자 설정에서 읽는다. 본인 백업 복원에 다른 주소가 들어 있어도 실제 연결 대상으로 사용하지 않는다.

## 개인 자료와 호환성

- owner는 기존 jlpt.sqlite·chat.sqlite·설정·복습 기록을 그대로 사용한다. 이동하거나 복사하지 않는다. 새 계정은 불변 UUID 하위 디렉터리에 새 학습·대화 DB를 갖는다. 다른 계정 DB를 열거나 공유하지 않는다.
- 서버는 요청별로 저장소를 선택한다. 비동기 처리 도중 공유 전역 변수를 사용자별로 바꾸지 않는다. 종료 시 열린 사용자 DB를 모두 닫고 계정 수 제한으로 저장소 개수를 제한한다.
- 학습 자료 기본 제공분은 새 계정에 새로 등록한다. 백업·복원·직접 문항 접근·음성 자료 선택도 본인의 저장소만 사용한다. 기존 owner의 가져온 문제/대화/정답률은 새 사용자에게 복제하지 않는다.
- 푸시 DB는 기존 기기에 owner 소유자를 기본 부여하는 컬럼을 비파괴 추가한다. 모든 HTTP 기기 동작은 로그인 사용자 ID로 필터링한다. 다른 소유자의 endpoint가 이미 있으면 이전 계정 연결 해제를 안내하고 소유권을 자동 이전하지 않는다.
- 이전 계정에 로그인할 수 없으면 현재 브라우저의 구독 해제를 먼저 실행한 뒤 새 계정으로 알림을 켠다. 다른 계정의 서버 행을 삭제하지 않고 브라우저에서 기존 구독을 해제해 새 endpoint를 받는다. 기존 endpoint는 다음 발송에서 만료 정리되며 계정 중지 상태에서는 보내지 않는다.
- 푸시는 발송 직전에 해당 계정이 활성 상태인지 확인한다. CLI는 기본 owner 대상만 유지한다. 다른 사용자의 기기를 ID 추측으로 발송/삭제/조회할 수 없다. 이미 중계 서비스가 접수한 알림은 회수 불가다.

## 화면과 운영

- 홈의 관리자 하위 메뉴에 계정 관리(/accounts/). 목록에 아이디·권한·활성 상태를 표시하고 추가·권한 저장·중지/재개·비밀번호 재설정을 제공한다. 평문 비밀번호를 저장 후 다시 표시하지 않으며 입력을 비운다. 자신의 사용자명/권한은 공통 헤더에서 확인할 수 있다.
- 일반 사용자에게 허용하지 않은 탭/편집 메뉴는 숨긴다. 직접 접근 시403을 표시하며 공개 홈으로 돌아갈 수 있다.
- 계정 관리와 앱 설치·알림 화면에 현재 로그인 아이디를 표시하고, 다른 계정 시험은 별도 브라우저/프로필 또는 비공개 창을 사용하라는 Basic 인증 안내를 둔다. OS/브라우저에 따라 PWA의 인증 정보가 별도로 유지될 수 있음을 알린다.
- Mac 업데이트 후 세 서버를 모두 재시작한다. 기존 auth.json을 삭제하거나 setup-auth를 다시 실행할 필요는 없다. 새 공통 계정 DB를 기존 비밀 자료와 함께 서버 정지 후 개인 백업한다. 운영 전 백업 권고와 구버전 롤백 금지 이유를 안내한다(구버전은 새 계정 권한을 모름).

## 완료 검증

- 기존 v1 인증/owner 데이터·설정·구독이 보존되고 잘못된 인증 파일은 fail closed.
- 관리자만 계정 생성·수정 가능, 마지막/고정 관리자 중지 방지, 중복ID·잘못된 권한·비밀번호 거부, 응답 비밀값 비노출, CSRF 차단.
- 서로 다른2명의 학습·대화·백업·복습·급수·기기 자료가 서버 재시작 후에도 분리됨. study/chat 권한별 직접 URL/API 우회 거부.
- 세 서버의 계정 중지·비밀번호 재설정·권한 회수가 캐시를 포함해 즉시 새 요청에 반영됨. 채팅 중지의 진행 중 요청 한계 시험.
- 일반 사용자의 Ollama 주소 직접 변경·악의적 백업 주소 우회 차단. PWA 구독 소유권 추가와 다른 소유자 ID/endpoint 추측 접근 차단.
- 임시 계정/DB의 브라우저 관리자 생성·권한 수정·모바일 화면 검증. 실제 Mac/폰 검증은 별도.
