# 계정별 학습·AI 권한 관리

관리자만 계정을 만들고 사용할 기능을 선택한다. 공개 홈·게시한 포트폴리오는 계속 공개이며, 학습·대화·비공개 콘텐츠는 권한을 검사한다.

## 업데이트

업데이트 전 세 서버를 정지하고 현재 `data/`와 별도로 설정한 데이터 경로를 개인 백업한다. 이후 저장소에서:

```sh
git pull --ff-only
npm ci
```

기존 실행 방식으로 학습·채팅·portfolio **세 서버를 모두 재시작**한다. LaunchAgent 예제 이름 그대로라면:

```sh
launchctl kickstart -k "gui/$(id -u)/org.starlightforge.portfolio"
launchctl kickstart -k "gui/$(id -u)/org.starlightforge.chat"
launchctl kickstart -k "gui/$(id -u)/kr.haru.jlpt"
```

위 이름은 실제 등록 이름에 맞춘다. 서버를 수동 실행했다면 각 터미널에서 기존처럼 실행한다. 기존 `auth.json`을 삭제하거나 `setup-auth`를 다시 할 필요가 없다. Nginx는 기존 `/`·`/api/portfolio/` 전달로 새 경로도 처리한다.

## 사람에게 사용할 계정 만들기

1. 기존 관리자 아이디·비밀번호로 로그인한다.
2. **홈 → 계정 관리** 또는 `https://starlightforge.duckdns.org/accounts/`에 접속한다.
3. 새 아이디, 비밀번호와 확인을 입력한다. 비밀번호는12자 이상이며 저장 후 다시 볼 수 없다.
4. **학습**, **AI 대화** 중 사용할 기능을 하나 이상 선택한다. 둘 다 선택할 수 있다.
5. 계정 추가 후 해당 사람에게 아이디·비밀번호와 사이트 주소를 직접 전달한다. 웹에서 초대 메시지를 보내지 않는다.

아이디는 영문·숫자·._-로1~64자이며 대소문자를 구분하지 않는다. 만든 뒤 바꾸거나 다른 사람에게 재사용하지 않는다. 계정은 고정 관리자를 포함해 최대30개다.

| 권한 | 허용 |
|---|---|
| 관리자 | 모든 기능·계정 관리·소개/프로젝트/이력서 편집 |
| 학습 | 본인의 JLPT·단어·문장·듣기·복습·학습 백업 |
| AI 대화 | 본인의 스텔라 대화·검색·대화 기록 |
| 모든 활성 계정 | 본인의 PWA 설치·알림 등록/해제/테스트 |

공개 콘텐츠가 아닌 관리·비공개 이력서·미게시 이미지는 관리자만 본다. 관리자가 일반 사용자의 학습·대화 내용을 들여다보는 별도 화면은 만들지 않았다. 관리자 개인 기록도 일반 사용자에게 제공하지 않는다.

## 변경·중지·비밀번호 재설정

등록한 계정에서 권한을 저장하거나 사용을 중지/재개한다. 비밀번호 재설정은 새 비밀번호와 확인을 입력한다. 권한·중지·비밀번호 변경은 서버 재시작 없이 **새 요청부터** 적용되며 기존 인증 캐시도 무효화한다. 진행 중인 AI 대화는 약2초 주기로 확인해 중단한다. 처리 중인 학습 요청은 끝날 수 있고 이미 푸시 서비스가 접수한 알림은 회수하지 못한다.

삭제 기능 대신 중지로 자료를 보존한다. 고정 관리자는 웹에서 중지·권한 변경·비밀번호 변경할 수 없다. 관리자 복구는 Mac의 `npm run setup-auth`를 사용한다. 이 명령은 현재/과거 아이디 충돌을 확인하고 고정 owner ID의 검증값을 바꾼다. 다른 사용자 자료를 덮어쓰지 않는다. 작업 후 세 서버 재시작을 권장한다.

브라우저 Basic 인증은 로그인을 기억할 수 있다. 다른 계정을 시험하려면 별도 브라우저 프로필이나 시크릿 창을 사용한다. 상단에 현재 아이디·권한이 보이므로 이를 먼저 확인한다. PWA는 Safari와 다른 인증 상태를 가질 수 있으며 웹에서 확실한 로그아웃을 보장할 수 없다.

## 자료 위치와 환경 변수

기존 관리자의 `jlpt.sqlite`, `data/chat/chat.sqlite`와 설정·복습·대화는 원래 위치에 둔다. 새 계정만 각 서버 데이터 디렉터리의 `users/<불변UUID>/` 아래 DB를 사용한다. 이름·권한을 바꿔도 다른 계정 자료를 배정하지 않는다. 일반 사용자의 학습 AI 주소는 관리자 설정을 사용하며, 사용자 백업에 다른 주소가 있어도 실제 서버 연결 주소가 되지 않는다.

- 공통 인증 원본: 기존 `AUTH_FILE`(기본 `data/auth.json`).
- 계정 DB: `AUTH_FILE` 옆 `accounts.sqlite`, 또는 `AUTH_USERS_FILE`.
- 세 서버는 **같은 AUTH_FILE과 같은 AUTH_USERS_FILE**을 사용해야 한다. 기본 설치는 자동으로 같은 경로다. 커스텀 DATA_DIR을 사용하면 기존 환경 변수도 함께 확인한다.
- 학습 사용자 자료: `DATA_DIR/users/<UUID>/jlpt.sqlite`.
- 대화 사용자 자료: `CHAT_DATA_DIR/users/<UUID>/chat.sqlite`.
- 푸시 DB/키: 기존 PUSH 경로 유지. 기존 기기는 owner 소유로 보존하고 새 등록은 계정별로 구분한다. Mac `send-push` CLI는 기본 owner 기기만 대상으로 한다.

폰의 같은 브라우저를 다른 계정으로 쓰면 이전 계정의 푸시 구독이 남을 수 있다. `앱 설치·알림`에서 현재 브라우저 구독을 해제한 뒤 새 계정으로 켠다. 이전 계정으로 로그인할 수 없어도 현재 브라우저 구독을 해제할 수 있다. 다른 사람의 서버 등록을 자동으로 가져오거나 삭제하지 않는다.

## 백업·롤백과 확인

세 서버와 수동 발송을 정지한 뒤 auth.json·accounts.sqlite 및 데이터 디렉터리 전체를 개인 저장소에 복사한다. SQLite의 WAL/SHM 파일이 있으면 함께 포함한다. 계정 DB에는 비밀번호 검증값이, 푸시 DB에는 구독 비밀값이 있으므로 Git·공개 파일·학습 JSON 백업에 넣지 않는다. 복원도 정지 상태에서 같은 경로로 하고 Mac 사용자 전용 권한을 유지한다.

새 계정 기능을 쓰기 시작한 뒤 서버 일부만 구버전으로 되돌리지 않는다. 구버전은 권한을 모르며 최신 DB와 일부 호환되더라도 같은 정책을 적용하지 못한다. 롤백이 필요하면 모든 서버를 멈추고 업데이트 전 코드·데이터 백업 전체를 함께 복원한다.

업데이트 후 관리자와 학습 전용·AI 전용 계정을 다른 프로필로 확인한다. 허용하지 않은 탭이 숨겨지고 직접 URL 접근도403인지, 새 계정 기록이 비어 있는지, 중지 후 접근이401인지 확인한다. 실제 Mac·휴대폰의 로그인·알림 수신은 해당 기기에서 점검한다.

기술·운영·사용 경험 기획 검토와 교차 코드 검토를 수행했고, Windows Node24.15.0에서 전체106개 테스트를 통과했다. 브라우저 검증은 실제 계정과 분리한 임시 자료를 사용했다.
